Common failure point

Permissions and hierarchy

When moderation or managed roles fail, check role order before changing bot configuration.

  1. 1Server OwnerAlways highest. Rob-bot cannot moderate the server owner.
  2. 2Admin / LeadershipOptional protected layer for trusted leads who should sit outside day-to-day bot moderation.
  3. 3Rob-botMust be above members it needs to moderate and above roles it needs to grant or remove.
  4. 4Moderator / SupportRecommended day-to-day staff layer. Its exact role name is server-owned.
  5. 5MentorReputation role. Default threshold: 500.
  6. 6ContributorReputation role. Default threshold: 150.
  7. 7BuilderReputation role. Default threshold: 50.
  8. 8Member rolesNormal community and interest roles.
  9. 9@everyoneDiscord's base role.

Rob-bot needs

  • View Channels, Send Messages, Embed Links, Attach Files, Read Message History
  • Manage Channels, Manage Threads, Manage Roles, Move Members
  • Moderate Members, Kick Members, Ban Members

Moderator / Support typically needs

  • Moderate Members for /warn, /timeout, /history, and /anonwho
  • Kick Members for /kick
  • Ban Members for /ban and /unban
  • Manage Threads when marking someone else's build-help solution
Moderation hierarchy rule

A moderator cannot target someone whose highest role is equal to or above their own. Rob-bot also refuses targets whose highest role is equal to or above Rob-bot's highest role.

Configuration reference

Channel and role map

These are logical resources Rob-bot needs. The displayed names are examples, not requirements. /setup auto discovers existing resources by normalized names and known aliases before proposing creation.

Do not rename the server to fit this table.

Use discovery-first /setup auto. Use the individual /setup … commands only for custom/manual overrides. Auto-setup never deletes, renames, moves, or merges existing server resources.

Ticket privacy

Keep the ticket category private from @everyone, then explicitly allow the staff roles that should handle tickets. Rob-bot grants access to the member who opens each ticket.

Environment variables

DISCORD_TOKEN

Required secret. Never commit or publish it.

ENVIRONMENT

Use production on the live host.

COMMAND_GUILD_ID

Recommended during setup for immediate guild-scoped command syncing.

SYNC_COMMANDS

Defaults to true. Disable only when you deliberately do not want startup command syncing.

ENABLE_MESSAGE_CONTENT

Set true only when Message Content is enabled in Discord.

ENABLE_BACKGROUND_TASKS

Keep true for scheduled quizzes, feeds, reports, App of the Week, voice reconciliation, and Pomodoro completion.

MAR_WIE_USER_ID

Authorizes /live. The current default already identifies Mar Wie's configured account.

MAR_WIE_TIKTOK_URL

Optional HTTPS TikTok URL for the Watch on TikTok button.

DATABASE_URL

Optional. Leave unset for persistent SQLite at data/marwie.db, or use the supported PostgreSQL configuration.

Restart expectations

Hosting or environment-variable changes require a bot restart. Normal Discord-side setup commands do not.
