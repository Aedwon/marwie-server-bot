Active vs. passive

Active features are intentionally triggered by a person. Passive features listen for Discord events or run scheduled work after configuration.

ActivePassiveStaff

Active

Slash commands, modals, select menus, and persistent buttons: someone explicitly asks Rob-bot to do something.

Passive

Message/voice listeners, cleanup, scheduling, polling, reporting, migrations, and restart reconciliation run automatically.

Troubleshooting

Fast checks for the most common setup failures.

Slash commands do not appear.

Verify the app was installed with applications.commands, SYNC_COMMANDS=true, and the correct COMMAND_GUILD_ID. Restart and inspect command-sync logs.

Moderation commands fail despite permissions.

Discord hierarchy still applies. Put Rob-bot above the target member’s highest role and verify Moderate Members, Kick Members, or Ban Members as applicable.

Reputation roles are not assigned.

Map Builder, Contributor, and Mentor with /setup role, give Rob-bot Manage Roles, and put its role above those managed roles.

Message logs contain no message text.

Enable Message Content Intent in the Developer Portal and set ENABLE_MESSAGE_CONTENT=true. The bot can deliberately run without content, so missing text does not mean it is offline.

A ticket is visible to everyone.

Fix the configured ticket category: deny @everyone View Channel and explicitly allow staff. New ticket channels use that baseline plus opener access.

AI updates are not posting.

Confirm ai_updates is mapped, the feature and background tasks are enabled, and the source is active. Test with /ai-source poll and check host logs.

What survives a restart?

Alembic migrations run on startup, persistent ticket/quiz views are re-registered, temporary voice state reconciles, and scheduled systems use durable session/timestamp state to resume safely.
