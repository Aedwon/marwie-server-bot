Staff tools

Discord permissions decide who can see most staff commands. Some commands add stricter runtime authorization; /live, for example, only publishes for Mar Wie’s configured Discord account.

Roles and hierarchy

Role order determines who Discord allows staff and Rob-bot to manage.

  1. 1Server OwnerAlways highest. Rob-bot can never moderate the server owner.
  2. 2Admin / LeadershipOptional protected layer for trusted leads who should sit outside bot moderation.
  3. 3Rob-botMust sit above members it may moderate and above Builder, Contributor, and Mentor.
  4. 4Moderator / SupportRecommended day-to-day staff role. The exact name is up to you.
  5. 5MentorReputation role. Default milestone: 500.
  6. 6ContributorReputation role. Default milestone: 150.
  7. 7BuilderReputation role. Default milestone: 50.
  8. 8Member rolesNormal community and interest roles.
  9. 9@everyoneDiscord's base role.

Rob-bot permissions

Give the bot only the permissions it needs:

  • View Channels, Send Messages, Send Messages in Threads
  • Embed Links, Attach Files, Read Message History
  • Manage Channels, Manage Threads, Manage Roles
  • Move Members
  • Moderate Members, Kick Members, Ban Members

Moderator / Support permissions

Moderate Members

Needed for /warn, /timeout, /history, and /anonwho.

Kick Members

Needed for /kick.

Ban Members

Needed for /ban and /unban.

Manage Threads

Lets staff mark a solution in someone else's build-help thread.

Also give this role access to private tickets and staff log channels.

Moderation hierarchy rule

A moderator cannot target someone whose highest role is equal to or higher than their own. Rob-bot also refuses a target whose highest role is equal to or higher than the Rob-bot role.

Channel and role map

These names are suggestions. Rob-bot stores the Discord IDs you connect, so your server can use different names.

Live notifications

live_announcements is the preferred destination for /live. If it is not configured, Rob-bot falls back to the normal announcements resource. live_ping_role is optional, and Rob-bot never uses @everyone or @here for this feature.

Ticket privacy

On the ticket category, deny @everyone → View Channel, then explicitly allow only the staff roles that should handle tickets. Rob-bot adds access for the member who opened each ticket.

Environment variables

DISCORD_TOKEN

Required secret. Never commit it or place it in documentation.

ENVIRONMENT

Use production on the live host.

COMMAND_GUILD_ID

Your Discord server ID. It gives immediate guild-scoped command syncing during setup.

ENABLE_MESSAGE_CONTENT

Use true when Message Content is enabled in the Discord Developer Portal.

ENABLE_BACKGROUND_TASKS

Use true for quizzes, feeds, reports, App of the Week, voice cleanup, and Pomodoro completion.

MAR_WIE_USER_ID

Authorizes /live. The current default is 703986808962285621, so the host does not need this variable unless Mar Wie’s Discord account changes.

MAR_WIE_TIKTOK_URL

Optional HTTPS tiktok.com URL. When set, /live includes a Watch on TikTok button. When unset, the announcement still posts without the button.

DATABASE_URL

Optional. Leave unset to use SQLite at data/marwie.db. PostgreSQL can be added later.
